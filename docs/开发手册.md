## 1. 快速开始

```bash
# 启动图形界面
python gui/app.py

# 跑教材标准向量自测（预期输出“测试通过”）
python tests/test_core.py
```

在别的程序里只想用算法、不要 GUI：

```python
from saes.core import s_aes_encrypt, s_aes_decrypt

cipher = s_aes_encrypt(0xD728, 0x4AF5)   # 0x24EC
plain = s_aes_decrypt(cipher, 0x4AF5)    # 0xD728
```

## 2. 项目结构

```
pro_2_SAES/
├─ gui/
│   └─ app.py            # GUI 层：tkinter 界面 + 输入解析 + 结果展示
├─ saes/
│   ├─ __init__.py
│   ├─ core.py           # 算法内核：S 盒、行移位、列混淆、密钥扩展、单分组加解密
│   ├─ multi_crypto.py   # 多重加密：双重、三重（48 bit）、中间相遇攻击
│   └─ cbc_mode.py       # 工作模式：CBC 加解密（长消息分组链接）
├─ tests/
│   └─ test_core.py      # 教材附录 D 标准向量自测
└─ docs/
    ├─ 用户指南.md
    ├─ 开发手册.md        # 本文件
    ├─ 测试结果.md
    └─ screenshots/      # 测试截图
```

分层原则：**算法层（`saes/`）不依赖界面，界面层（`gui/`）不含算法细节**。
因此算法层可以直接被命令行工具、服务端或其他 GUI 复用，这也是本项目把内核单独抽成包的原因。

## 3. 数据约定（重要，接错必出错）

| 约定 | 说明 |
| --- | --- |
| 数据单位 | 分组固定 **16 bit**，在代码里统一用 Python `int`（0 ~ 0xFFFF）表示 |
| 密钥长度 | 单次 S-AES 16 bit；双重 32 bit；三重 48 bit |
| 状态表示 | 16 bit 整数拆成 4 个半字节 `n0 n1 n2 n3`（高位到低位），对应状态矩阵**列优先**：`n0=左上, n1=左下, n2=右上, n3=右下` |
| 十六进制输入 | 不带 `0x` 前缀，大小写均可；单次密钥/明文 4 个字符，双重密钥 8 个，三重密钥 12 个 |
| 多分组形式 | 密文分组用空格分隔，例如 `08D7 4BF1 1FE0` |
| 输出格式 | 统一 `f"{value:04X}"` 打出 4 位大写十六进制 |

> 状态“列优先”是该实现唯一的易错点：如果按行优先拆半字节，行移位与列混淆会得到不同的（错误）结果。
> 判断是否接错的最快方法就是跑 `tests/test_core.py` 里的 `D728 + 4AF5 → 24EC`。

## 4. 算法内核 `saes/core.py`

### 4.1 常量表

| 名称 | 类型 | 含义 |
| --- | --- | --- |
| `S_BOX` | 4×4 `int` 列表 | 半字节替换盒，按 `S_BOX[n >> 2][n & 0x3]` 索引 |
| `INV_S_BOX` | 4×4 `int` 列表 | 逆替换盒 |
| 轮常数 | 硬编码 `0x80`、`0x30` | Rcon1、Rcon2 |

### 4.2 接口一览

| 函数 | 签名 | 返回 | 说明 |
| --- | --- | --- | --- |
| `sub_nibbles` | `sub_nibbles(word: int, inverse: bool = False) -> int` | 替换后的 16 bit | 对 4 个半字节逐一查 S 盒；`inverse=True` 走逆盒 |
| `shift_rows` | `shift_rows(word: int, inverse: bool = False) -> int` | 移位后的 16 bit | 交换第 2、4 个半字节（`n1 ↔ n3`）；加解密操作相同，`inverse` 仅为接口对称 |
| `gf_mult` | `gf_mult(a: int, b: int) -> int` | 4 bit 乘积 | GF(2⁴) 乘法，约简多项式 x⁴+x+1（实现上用 `a ^= 0x3` 处理溢出位） |
| `mix_columns` | `mix_columns(word: int, inverse: bool = False) -> int` | 混淆后的 16 bit | 正向矩阵 `[[1,4],[4,1]]`，逆向 `[[9,2],[2,9]]`；按列 (n0,n1)、(n2,n3) 计算 |
| `expand_key` | `expand_key(key: int) -> tuple[int, int, int]` | `(K0, K1, K2)` | 由 16 bit 主密钥扩展出 3 个轮密钥 |
| `add_round_key` | `add_round_key(state: int, round_key: int) -> int` | 异或结果 | 轮密钥加，即按位异或 |
| `s_aes_encrypt` | `s_aes_encrypt(plaintext: int, key: int) -> int` | 密文 16 bit | 单分组加密 |
| `s_aes_decrypt` | `s_aes_decrypt(ciphertext: int, key: int) -> int` | 明文 16 bit | 单分组解密 |

所有函数均为**纯函数**（不修改入参、无全局状态、无副作用），可以安全地在循环、多线程或单元测试中反复调用。

### 4.3 密钥扩展

```
w0 = key >> 8          w1 = key & 0xFF
w2 = w0 ⊕ Rcon1 ⊕ SubWord(RotWord(w1))     w3 = w2 ⊕ w1
w4 = w2 ⊕ Rcon2 ⊕ SubWord(RotWord(w3))     w5 = w4 ⊕ w3
K0 = w0||w1            K1 = w2||w3           K2 = w4||w5
```

`RotWord` 交换一个字节内的两个半字节；`SubWord` 对两个半字节分别查 S 盒。
实现中 `RotWord`/`SubWord` 借用了 `sub_nibbles`，避免重复写一份查表逻辑。

### 4.4 加密 / 解密流程

```
加密：  S = P ⊕ K0
        第1轮：SubNibbles → ShiftRows → MixColumns → ⊕ K1
        第2轮：SubNibbles → ShiftRows → ⊕ K2          （末轮不含列混淆）
        C = S

解密：  S = C ⊕ K2
        逆第2轮：InvShiftRows → InvSubNibbles → ⊕ K1 → InvMixColumns
        逆第1轮：InvShiftRows → InvSubNibbles → ⊕ K0
        P = S
```

> `InvShiftRows` 与 `InvSubNibbles` 作用在不同的维度上（行 / 半字节替换），二者可交换，
> 所以代码里先移位后替换，与课本顺序等价。

### 4.5 复杂度

单次加解密为常数时间：两轮运算，每轮固定次数的半字节替换、移位、GF(2⁴) 乘法与异或。
在 Python 下实测约 **19 µs/次**（本机 Python 3.13，由 65536 次加密 + 65536 次解密耗时 2.45 s 推算），
这也说明 S-AES 只适合教学：分组与密钥都太短。

## 5. 多重加密 `saes/multi_crypto.py`

### 5.1 接口一览

| 函数 | 签名 | 返回 | 说明 |
| --- | --- | --- | --- |
| `double_encrypt` | `double_encrypt(plaintext: int, key32: int) -> int` | 密文 | `C = Enc(K2, Enc(K1, P))` |
| `double_decrypt` | `double_decrypt(ciphertext: int, key32: int) -> int` | 明文 | `P = Dec(K1, Dec(K2, C))` |
| `triple_encrypt` | `triple_encrypt(plaintext: int, key48: int) -> int` | 密文 | `C = Enc(K3, Dec(K2, Enc(K1, P)))` |
| `triple_decrypt` | `triple_decrypt(ciphertext: int, key48: int) -> int` | 明文 | `P = Dec(K1, Enc(K2, Dec(K3, C)))` |
| `meet_in_the_middle_attack` | `meet_in_the_middle_attack(plaintext: int, ciphertext: int, extra_pairs: list[tuple[int, int]] \| None = None) -> list[tuple[int, int]]` | `[(K1, K2), ...]` | 对双重加密做中间相遇攻击 |

### 5.2 密钥布局

| 密钥 | 位宽 | 拆分方式 |
| --- | --- | --- |
| `key32` | 32 bit | `K1 = key32 >> 16`，`K2 = key32 & 0xFFFF`；即 `0x4AF51234` → K1=`4AF5`, K2=`1234` |
| `key48` | 48 bit | `K1 = key48 >> 32`，`K2 = (key48 >> 16) & 0xFFFF`，`K3 = key48 & 0xFFFF` |

三重加密采用 **EDE（加密-解密-加密）** 结构，与 3DES 的习惯一致：中间一步是解密，
这样在 `K1 == K2 == K3` 时可以退化为单次 S-AES。

### 5.3 中间相遇攻击

**原理**：`C = Enc(K2, Enc(K1, P))`，令中间值 `M = Enc(K1, P) = Dec(K2, C)`，
则只需分别枚举 K1、K2（各 2¹⁶ 次），靠 `M` 的碰撞把 2³² 的密钥空间降到 2×2¹⁶。

**实现要点（两处关键设计）**

1. **中值表存列表而不是单值**：`Enc(K1, P)` 对 K1 不是单射（65536 个 K1 只产生约 41510 个不同中值），
   若每个中值只保留一个 K1，真正的 K1 会被后来的候选覆盖而漏解。代码用 `dict[mid] -> [K1, ...]`。
2. **用第二对明密文复核**：16 bit 分组下，单对明密文会产生约 **65522** 个候选（几乎每个 K2 都能碰撞上），
   无法唯一定位；`extra_pairs` 中的每一对都用 `double_encrypt` 复核，命中后候选收敛到 1 个。

**参数与返回**

| 参数 | 说明 |
| --- | --- |
| `plaintext` / `ciphertext` | 已知的一对明密文（16 bit） |
| `extra_pairs` | 额外 `[(P2, C2), ...]`，用于剔除假阳性；传 `None` 或不传则返回全部候选 |

返回值为 `[(K1, K2), ...]`，元素唯一（同一 K2 只遍历一次、同一 K1 只入表一次）。
**该函数是纯计算函数，不含任何“对照真实密钥”的判断**——界面层把结果与真实密钥比对并标注“一致”，属于展示逻辑。

**性能**：本机实测约 **2.4 秒**（仅碰撞）/ **5.6 秒**（带第二对复核），内存峰值为主表的 6 万余条记录。

## 6. CBC 工作模式 `saes/cbc_mode.py`

### 6.1 接口一览

| 函数 | 签名 | 返回 | 说明 |
| --- | --- | --- | --- |
| `cbc_encrypt` | `cbc_encrypt(plaintext_bytes: bytes, key16: int, iv16: int) -> list[int]` | 密文分组列表（每项 0~0xFFFF） | `C_i = Enc(K, P_i ⊕ C_{i-1})`，`C_0 = IV` |
| `cbc_decrypt` | `cbc_decrypt(ciphertext_blocks: list[int], key16: int, iv16: int) -> bytes` | 明文字节串 | `P_i = Dec(K, C_i) ⊕ C_{i-1}` |

### 6.2 填充与格式约定

| 项 | 当前实现 | 说明 / 局限 |
| --- | --- | --- |
| 分组长度 | 2 字节 | 与 16 bit 分组对应 |
| 填充方式 | 长度为奇数时在末尾补 **1 个 `0x00`** | 不是 PKCS#7，**无法区分“补的 0x00”和“原文末尾本来就是 0x00”**；生产实现应改用 PKCS#7 |
| 编码 | GUI 层把输入文本按 **UTF-8** 编码后再分组 | 英文/ASCII 正常，中文会按 UTF-8 多字节拆分，解密后仍是原文（但分组数变多） |
| IV | 16 bit，由调用方传入，加解密双方必须相同 | 界面里默认 `0000` 便于复现；实际使用应 `secrets.randbits(16)` 随机生成并随密文传输 |
| 完整性 | **无** MAC/校验 | 篡改无法被发现，只能靠上层加 HMAC 或改用 AEAD 模式 |

### 6.3 错误传播特性

`C_i` 同时参与 `P_i` 的解密和 `P_{i+1}` 的异或，所以篡改一个密文块会：

1. 让被篡改块本身解密成完全随机的数据；
2. 让下一个块出现**对应比特的翻转**（可控篡改点）；
3. 再往后的块不受影响，仍能正常解密。

界面演示：把 `6316` 改成 `6317` 后，`HELLO CBC MODE` 变成 `HE<NO!CBC MODE`（详见 [测试结果](测试结果.md) 第 5 关）。

## 7. 界面层 `gui/app.py`

### 7.1 类结构

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `SAESGui(root)` | 类 | 构造函数负责建 `ttk.Notebook` 和三个选项卡，无返回值 |
| `notebook` / `tab_basic` / `tab_multi` / `tab_cbc` | 控件 | 选项卡容器 |
| `basic_key` / `basic_input` / `basic_output` | `Entry` / `Text` | 第 1、3 关的控件 |
| `multi_key` / `multi_input` / `multi_output` | `Entry` / `Entry` / `Text` | 第 4 关的控件 |
| `cbc_key` / `cbc_iv` / `cbc_input` / `cbc_output` | `Entry` / `Entry` / `Text` / `Text` | 第 5 关的控件 |

窗口固定为 `900x640`（`minsize` 同值），保证第 4、5 关的输入框不会被裁切。

### 7.2 回调（按钮 → 处理函数）

| 按钮 | 处理函数 | 输入解析规则 |
| --- | --- | --- |
| 单次加密 | `do_basic_encrypt()` | 输入恰好 4 个字符 → 当作 16 bit 十六进制；否则按 ASCII 字符串处理（奇数长度补 `\x00`，每 2 字节一块） |
| 单次解密 | `do_basic_decrypt()` | 输入含空格 → 按“空格分隔的密文块”逐块解密并拼成字符串；否则当作单个 16 bit 密文 |
| 双重加密/解密 | `do_multi(is_encrypt, is_triple)` | 密钥长度必须为 8（双重）或 12（三重）个十六进制字符，否则弹错误框 |
| 运行中间相遇攻击 | `do_mitm()` | 用当前 32 bit 密钥生成两对已知明密文（第二组明文 `0x1234`，冲突时换 `0x5678`），调用攻击函数并格式化输出 |
| CBC 加密/解密 | `do_cbc_encrypt()` / `do_cbc_decrypt()` | 加密按 UTF-8 取字节；解密要求输入为空格分隔的十六进制块 |

所有回调都包在 `try/except` 中，异常统一用 `messagebox.showerror("错误", str(e))` 提示，避免界面卡死。

### 7.3 新增一个功能的步骤（扩展点）

1. 在 `saes/` 里实现纯函数（不碰任何界面代码）；
2. 在 `tests/` 里补一条标准向量或往返测试；
3. 在 `SAESGui.setup_xxx_tab()` 里加控件，在回调里只做“取值 → 调算法 → 显示”；
4. 在 [用户指南](用户指南.md) 补使用说明、在 [测试结果](测试结果.md) 补一条截图记录。

## 9. 二次开发建议

| 需求 | 建议做法 |
| --- | --- |
| 命令行/服务端调用 | 直接 `from saes.core import s_aes_encrypt`，不要 import `gui`（会拉起 tkinter 窗口依赖） |
| 加密文件 | 复用 `saes.cbc_mode`：读字节 → `cbc_encrypt` → 以 4 位十六进制文本或二进制落盘；解密反向 |
| 加完整性 | 在 CBC 之外再算 `HMAC-SHA256(K_mac, 密文)`，解密前先校验；或改用 AEAD 思路（先 MAC 后加密） |
| 改填充 | 把 `cbc_encrypt` 的“补 `\x00`”换成 PKCS#7（补 `n` 个字节值 `n`），并在 `cbc_decrypt` 末尾按最后一个字节值裁掉，注意校验 `1 ≤ n ≤ 16` |
| 提升 MITM 速度 | 只在需要唯一解时传 `extra_pairs`；表可改成 `dict[int, array]` 并用 `array('H')` 压缩，内存与常数都能降一档 |
| 换 S 盒做实验 | 只改 `S_BOX` / `INV_S_BOX` 两个常量即可（注意逆盒必须与正盒严格对应，否则加解密不互逆） |

## 10. 已知限制

1. **分组太短**：16 bit 分组意味着字典攻击/碰撞类攻击代价极低，只适合教学，不能用于真实数据。
2. **中间相遇攻击的假阳性**：单对明密文约有 6.5 万个候选，必须补第二对才能唯一确定密钥（见 5.3）。
3. **ASCII 模式与十六进制模式的歧义**：基础选项卡“4 个字符就按十六进制解析”，
   所以像 `ABCD` 这样的 4 字符 ASCII 串会被当成十六进制数 `0xABCD`。
   需要加密 4 字符 ASCII 时，可在界面上改用 CBC 选项卡（按字节处理），或先把算法层当库调用。
4. **解密输出的字符集**：ASCII 路径按字节 `chr()` 拼字符串，非 ASCII 内容会显示为乱码（与作业“输出可为乱码”的要求一致）。
5. **CBC 无填充标准、无完整性保护**：见 6.2。
6. **界面无 IV 随机化按钮**：IV 需手工输入，取 `0000` 只为便于复现截图。

## 11. 代码规范说明

| 规范 | 本项目做法 |
| --- | --- |
| 命名 | 变量/函数用 `snake_case`（`sub_nibbles`、`round_key`），类用 `CamelCase`（`SAESGui`），避免单字母名（`a`、`b` 仅用于 GF 乘法的数学参数） |
| 注释 | 只在算法步骤、非直观位运算、易错点处写注释（如 `gf_mult` 的约简、状态列优先、假阳性说明），行内注释解释“为什么”而不是复述代码 |
| 模块化 | 算法内核 / 多重加密 / 工作模式 / 界面四层分离，每个公开函数职责单一、无副作用 |
| 复用 | 半字节拆分、S 盒查表、`gf_mult` 都被 `mix_columns`、密钥扩展等复用；界面层只调用算法层 |
| 依赖 | 只用标准库，保证任何装了 Python 的机器都能直接跑 |
